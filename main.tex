\chapter*{摘\quad 要}
\markboth{摘要}{摘要}
\phantomsection
\addcontentsline{toc}{chapter}{摘\quad 要}

{\setlength{\parindent}{2em}
随着智慧校园建设的推进，教务管理、校园生活、实验室使用和办事流程等信息大量分散在规章制度、通知公告与办事指南中，学生检索成本高，管理人员重复答疑多，不同渠道的回答口径也不一致。通用大语言模型具备较强的自然语言理解与生成能力，但缺乏校本知识，直接回答校园问题容易产生事实性错误，且难以说明答案来源。针对上述问题，本文设计并实现了一个基于大模型的校园智能问答系统。系统以学校公开资料为知识源，采用 Vue 3 与 FastAPI 构建前后端分离的 Web 应用，使用 MySQL 保存业务数据，使用向量数据库保存知识片段索引；在数据处理阶段完成文档解析、清洗、结构感知分块与向量化，在问答阶段采用 BM25 与稠密向量双路召回、倒数排序融合和交叉编码器重排，并将检索到的证据与问题一并送入大模型，通过提示词约束生成带引用编号的回答，证据不足时执行拒答。系统还包括用户与权限管理、资料管理、问答历史、满意度反馈和管理统计等功能。本文完成了系统的需求分析、总体设计、关键模块实现方案与测试方案设计，给出了检索、生成、引用溯源和权限控制的具体实现思路，并设计了纯大模型问答与不同检索策略的对照实验，为后续系统联调和效果验证提供了可复现的依据。\par
}

\chapter*{Abstract}
\markboth{Abstract}{Abstract}
\phantomsection
\addcontentsline{toc}{chapter}{Abstract}
\begingroup
\rmfamily
\setlength{\parindent}{0pt}
\setlength{\parskip}{6pt}
With the advancement of smart campus construction, information about academic affairs, campus life, laboratory use, and administrative procedures is scattered across regulations, notices, and service guides. Students spend considerable time searching for answers, and different channels sometimes provide inconsistent information. Generic large language models lack institution-specific knowledge; when asked campus-related questions, they may produce plausible but incorrect answers and usually cannot indicate the source. To address these problems, this thesis designs and implements a campus intelligent question answering system based on a large language model. The system uses publicly available campus documents as its knowledge source and adopts a front-end and back-end separated architecture built with Vue 3 and FastAPI. MySQL stores business data, and a vector database stores knowledge chunk indexes. Documents are parsed, cleaned, split in a structure-aware manner, and vectorized. For question answering, BM25 and dense vector retrieval are combined, reciprocal rank fusion merges the candidates, and a cross-encoder reranks the results. The question and retrieved evidence are sent to the large language model, and prompt constraints require the answer to cite the evidence; when evidence is insufficient, the system refuses to answer. The system also provides user and permission management, document management, question answering history, satisfaction feedback, and administrative statistics. This thesis completes requirement analysis, overall design, key module implementation scheme, and test plan design, and designs a comparative experiment between direct large-model answering and different retrieval strategies, providing a reproducible basis for subsequent integration and evaluation.
